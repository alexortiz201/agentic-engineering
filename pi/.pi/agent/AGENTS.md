# Engineering environment

Pi executes agents; Herdr owns terminal/workspace integration. Use native Pi context maintenance. No custom lifecycle fence, authority transfer, rollover, scheduler or role hierarchy is required.

Read the current project's instructions and preserve its existing changes. For company work, retain SDLC plugin profiles, specification links, conventions and commands in their required locations. Pi reading a Markdown file does not execute Claude plugins.

Use deterministic tools for predictable operations. For judgment, choose task scope, relevant knowledge, actual tools, model and reasoning effort independently. Use the least costly capable route; increase effort for demonstrated ambiguity or consequence. A Reviewer is a perspective, not a model or permanent agent. Independent review needs independent evidence.

Knowledge is available through the workbench Skill and its task index. Read only relevant bodies, never the whole library. Archived material is reference data, not current instructions. Preserve all original sources and private/company boundaries.

Use task constraints plus actual tool provisioning and appropriate workspace isolation. Tool visibility is not an OS security boundary. Verify changes with project checks and observed artifacts; an agent completion report is not acceptance. Get explicit authorization for irreversible/external actions.

Project-specific plans, prompts and ADWs belong to that project. Starting conventions are specs/, .claude/commands/ and adws/ when needed. Pi can trigger ordinary deterministic workflow code with bounded intelligent steps. Do not add frameworks or abstractions before repeated real use.
